# 2026.241.1506 — fix: the charly-dev binary sync no longer exists — correct the internals skills

## Summary of changes

`opencharly/charly#454` folded the `charly-dev` candy into charly's project manifest, so its
`copy: bin/charly` resolves against the **repo root**; `charly#457` then deleted `candy/` entirely.
The dual-path sync these skills document — repo-root `bin/charly` kept in step with
`candy/charly-dev/bin/charly` by `task build:binary` — **no longer exists, and neither does the
directory.**

Published as-is, this candy teaches contributors to run

```bash
cp bin/charly candy/charly/bin/charly           # REQUIRED follow-up
```

against a path that is gone, and warns at length about a *"dual-path gotcha"* that has been
designed out.

### Seven corrections, all in skill prose

| Where | Was | Now |
|---|---|---|
| two-binaries bullet | "a CalVer-stamped build **plus a `candy/charly-dev/bin/charly` copy**" | one build, one path |
| side-effects bullet | "keeps the dual path … in sync (a manual `go build -o` does not)" | writes ONE path; a manual `go build -o bin/charly` is equivalent |
| Quick Reference table | "**Also copies to** `candy/charly-dev/bin/charly`" | the candy copies `bin/charly` directly |
| cache-invalidation ¶ | "Updating `candy/charly-dev/bin/charly` does invalidate…" | "Updating `bin/charly` does invalidate…" |
| "dual-path gotcha" ¶ | two paths "must stay in sync", with a required `cp` | what actually happens now — **and why it used to bite** |
| packaging pointers ×2 | `candy/charly/charly.yml` | `packaging/charly.yml` (moved by #457) |

The gotcha paragraph is *replaced rather than deleted* — it now records that forgetting the sync
baked the **previous** binary into every check bed, silently, because nothing failed, and that
declaring the candy where the path already resolves removed the second path and that whole class of
mistake. A reader who hits an old blog post or an old branch should be able to tell what changed.

**Zero references to `candy/charly-dev` or `candy/charly` remain in this manifest.**
