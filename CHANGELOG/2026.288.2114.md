# 2026.288.2114 — docs(skill): filter a PR list on `merged_at`, never on `merged` — it is null for MERGED PRs

## Summary

Adds **one invariant** to the `git-workflow` skill: **filter a PR list on `merged_at`, never on `merged`.**

The GitHub pull-list API returns `merged: null` for PRs that HAVE merged. A session that reads that as "not merged"
reports landed work as still in flight — and the session that made this error called a landed fix *"unpushed"*, which
understated an entire clause of the wave it was auditing. `merged_at` carries the timestamp or nothing at all, and
`state=all` is what finds a merged PR.

The bullet also carries the same defect in its other field, because they cost the same and are worth one line:
**`per_page` is a window, not an inventory** — a name or item absent from the newest N results has not been shown to be
absent from the world, *and a field that is null for "unknown" and null for "no" cannot be counted with.*

**Why it belongs here and not elsewhere**: landing mechanics are owned by this skill (the authoritative-copy registry), and
this one is read at the moment a session audits a wave's landing state.
