# 2026.271.0810 — docs(git-workflow): retire the rerun-label channel — body-fix rerun is manual

## Summary

Retires the **`rerun`-label** guidance from the `git-workflow` and `repo-setup` skills, replacing
it with the **manual `gh run rerun <run-id>`** body-fix path. Companion to the org config
removal in **opencharly/.github#134**.

### Why (R1)

A required/ruleset workflow fires ONLY on the default `pull_request` activity types
(`opened, synchronize, reopened`) and IGNORES `on.types` — MEASURED and confirmed by the GitHub
docs ("Troubleshooting rules": *"Any filters you specify for the supported events are ignored —
for example, branches, branches-ignore, paths, types and so on"*). So a body edit can never
re-trigger the gate. The org previously bridged this with a `rerun` label + a scheduled sweep —
but a label can be added for ANY reason (e.g. after a comment), and the sweep then re-ran the
gate **without a body change**. That channel is now RETIRED; the body-fix rerun is explicit.

### Changed

- `git-workflow` skill body: the "required workflow fires only on default types" note; the
  "body-only fix" paragraph; the `workflow_dispatch` note; the "FINISH THE BODY BEFORE THE
  PUSH" bullet.
- `git-workflow` → `references/validator-and-calver.md`: the body-only-BLOCK remedy.
- `repo-setup` skill body: the landing-chain step 4 and the workflow list.

Each now says: re-run the EXISTING failed run with `gh run rerun <run-id>` (find it via
`gh run list --repo <r> --json databaseId,headSha,conclusion`) — a re-run reuses the SAME
`GITHUB_SHA` and updates THAT run's `validate / validate` check in place (no duplicate, clears
POISON) — or push an empty re-freeze commit. No automatic label channel.
