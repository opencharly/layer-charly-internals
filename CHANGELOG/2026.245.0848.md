# 2026.245.0848 — docs(skills): plugin skill — external-first placement default, legacy source: builtin clarity

## Summary

The plugin skill (charly-internals:plugin, owned by this repo) presented the
compiled-in placement as a first-class default: the example manifest used
`source: builtin`, and no text stated the placement DECISION procedure. A
fresh plugin integration (the herdr plugin) consequently went down the
compiled-in path (charly-module go.mod require + pluginsgen) before the
boundary law's external-first strategic direction was consulted. This change
makes the default explicit and repairs the confusing advice:

- The example manifest now shows the **external github-ref `source:` form as the
  default for new plugins** (out-of-tree, out-of-process by word) with a comment
  marking `source: builtin` as the legacy in-repo linkage form.
- A new **"Placement — EXTERNAL by default for new plugins"** section in the SKILL
  content: authored placement-agnostic (F8), shipped external (composed via the
  `@github.com/<org>/<repo>/candy/<name>:<ref>` candy ref, connected by word at
  runtime with ZERO charly-module changes); `compiled_plugins:` is a
  per-charly-build decision for curated kernel-adjacent builtins only, and the
  strategic direction migrates those external over time.
- The **authoring-recipes reference** now opens with the same placement-default
  guidance (boundary-law default: a plugin reaches the kernel by resolving into
  an envelope a mechanism consumes).
- The **Verification** bullet contextualizes the legacy `source: builtin` rule.
