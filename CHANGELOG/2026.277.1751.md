# 2026.277.1751 — docs(plugin): point the compiled-in recipe at --dev-plugin for a local checkout

## Summary

The `plugin` skill's `authoring-recipes` reference explains how to author a **compiled-in** plugin candy —
a candy named in charly's `compiled_plugins:` and linked into `bin/charly` — and it stopped one step short
of the thing an author actually needs: how to test that candy against an **unmerged** checkout. A
compiled-in candy resolves from the module proxy at its pinned `require`, so a stock binary runs the
**published** candy and no bed can fail on your edit — the trap `opencharly/charly#775` exists to close.

This adds that step to the recipe's compiled-in list, pointing at the sanctioned mechanism
(`opencharly/charly#788`, merged 2026-10-04T15:28:14Z / tag `v2026.277.1528`):
`scripts/bootstrap-charly.sh --dev-plugin <candy-name>=<repo-checkout>`, what it writes (a separate
`go.work.dev`, selected only under an explicit `GOWORK=`, so the committed `go.work` / `go.work.sum` stay
byte-identical), the two validations `pluginsgen` runs before compiling, and how to prove the changed path
**executed** — the `go version -m` `(devel)`-vs-module-proxy discriminator (necessary, not sufficient) and a
symbol-set difference over `go tool nm` rather than a package-anchored `grep`, which matches every plain
function and no method at all.
