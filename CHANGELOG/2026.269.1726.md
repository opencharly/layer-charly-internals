# 2026.269.1726 — docs(git-workflow): correct the body-fix mechanism to the MEASURED truth (`rerun` label)

## Summary

Correct the `git-workflow` skill's body-fix mechanism to the **measured** truth:
a body-only fix is cleared by adding the **`rerun` label**, not by an `edited`
trigger (which never fires the org required workflow).

### RCA (8-step, R1)

**Unexpected.** This repo's prior PR (#24) taught that a body edit re-runs the
gate via the `edited` trigger. Live testing disproved it.

**Mechanism (four live experiments):**

| # | Experiment | Result |
|---|---|---|
| 1 | Plain per-repo workflow `on: pull_request: [edited]` | **FIRES** |
| 2 | Plain per-repo workflow `on: pull_request: [labeled]` | **FIRES** |
| 3 | The org **required** workflow lists `edited`; edit the body | **NO RUN** (×3) |
| 4 | The org **required** workflow already lists `ready_for_review`; draft→ready | **NO RUN** |

Experiments 3–4 prove the org **required workflow ignores `on.types`** — it acts
only on `opened`/`synchronize`/`reopened`. So #24's `edited` channel never worked.
The correct channel is the org's plain per-repo **`rerun-listener`** (distributed
by `opencharly/.github`'s `distribute-rerun-listener`): adding a `rerun` label
re-runs THIS head's failed `charly/pr-validator` run — same `GITHUB_SHA`, SAME
check run updated in place (no duplicate, clears POISON), re-reads the body.

### Fix

Swept all three sites (claim-keyed, R5):
- **"THE BODY-BEFORE-PUSH RULE"** — states the required workflow fires only on
  the default types; the body-only fix is the `rerun` label / `gh run rerun`.
- **"FINISH THE BODY BEFORE THE PUSH"** invariant — same correction.
- **the `validator-and-calver` reference** — same correction.
