# 2026.272.1021 — docs(agents): OpenCode monitor+control — agent_progress + agent_control, stop-and-confirm

## Summary

Add an **OpenCode section** to the `agents` skill **source** documenting how to MONITOR
and CONTROL agents/subagents in OpenCode — the `agent_progress` + `agent_control` tools —
and **retire the `~50-message` / turn-count rotation trigger** from that same source. This
repo owns the `internals` family's `skill:` entities; the marketplace corpus is
regenerated from them.

The new section (in the `agents-skill` `content`, plus a new `triggers` row) covers:

- **`agent_progress`** (monitor): artifact / cadence / loop / idle verdicts; **a message is
  an ASSISTANT TURN, never a stall signal**; diagnose from the transcript.
- **`agent_control`** (control): `list` / `interrupt` / `delete` / `wait` /
  `confirm_stopped`. **Stop = `interrupt`/`delete` and CONFIRM it stopped.** **A rotation
  is STOP + spawn** — stop the predecessor and confirm no new turns BEFORE spawning the
  successor.
- The OpenCode control primitives are **first-class** (`ctx.session.interrupt`/`wait`;
  `opencode session delete`; the API equivalents) — never claim OpenCode cannot stop a
  subagent.

New dispatcher trigger: `"Monitor a subagent's progress / stop a stalled, idle, or looping
worker"`.

**The turn-count sweep (round 2).** The `Rotate on stall` section's hard trigger previously
read *"…or its session passes **~50 messages without a produced artifact**"* — a turn-count
stop rule that contradicts the umbrella rulebook's monitor rule (**artifact and cadence,
never a counter**; *"Never rotate an actively-working session for its turn count"*) and the
new `agent_progress` verdicts. It is now: the trigger is the **orchestrator re-briefing the
SAME task more than twice** — never a session turn/message count.
