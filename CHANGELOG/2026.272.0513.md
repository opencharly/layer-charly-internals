## Summary

Codifies two field-learned engineering lessons at the skills that own them, both drawn from live incidents tracked in the umbrella.

**Lesson 1 — RCA discipline (R1), `root-cause-analyzer` skill.** A new section, `## Failure-signature enumeration and measurement discipline`, binds every RCA to three rules:

- **Enumerate EVERY distinct failure signature FIRST**, before naming any cause — bucket the raw log (`grep -o 'cause="[^"]*"' <log> | sort | uniq -c | sort -rn`, adapted to the log's key). One symptom usually has multiple INDEPENDENT signatures.
- **Never verify a fix from a single sample** — measure against a stable baseline over a window in which the system is PROVABLY UP. A zero reading during downtime is not evidence; it is the expected output of a system that could not attempt the operation.
- **Distinguish "the symptom stopped because it was fixed" from "it stopped because the system was down."** Both read as zero failures; only the first is a fix.

Includes the worked example: three independent issues (snapshot loop + blocking plugin + stale worktree) under one "server restarts" symptom.

**Lesson 2 — plugin/tooling integration dependency, `agents` skill.** A new section: a plugin resolves **different pieces from different refs** — the plugin **code** may load from the workspace/origin checkout, while a **backend script it shells out to** resolves from a **pinned submodule** (or `@github` ref). Those refs advance independently, so a plugin can be **HALF-USABLE**. A tool failure of the form **"X not found — sync the pin"** is a **PIN-LAG**, not a plugin defect. Concrete case: `coord_comment` failed while `coord_watch` worked — same plugin, but `coord_comment` resolves `marketplace/scripts/coord.sh` and `coord_watch` resolves `marketplace/scripts/gh_watch.sh`; `coord.sh` had merged after the pinned `marketplace` gitlink, so the tool reported the designed "sync the marketplace pin" message.

Both are generic (no repo/plugin-specific names in the rules), sharp, and self-contained; the dispatcher entry SKILL.md carries each directly (Lesson 1's `root-cause-analyzer` SKILL.md is entirely the entry file; Lesson 2 sits in the `agents` entry SKILL.md).
