# 2026.270.1211 — docs(plugin-skill)!: state the uniform schema rule — no schema-less plugin

## Summary

Correct the **source** of the marketplace `plugin` skill's `cue-schema-contract` reference, which still *taught* the deleted waiver:

> *"An INPUT-LESS plugin (no `input_def` on any capability) ships NO schema — the load gate waives it (the former requirement forced dozens of near-identical stub files)."*

That is exactly the exception the R5 cutover (**opencharly/charly#712**) removes. The source now states the uniform rule:

- **EVERY plugin ships a non-empty, self-contained CUE schema** — the *"doc schema"* where a capability declares no structured input (a pass-through command, a substrate kind, a deploy target). There is no input-less exemption.
- A capability **with** a structured input declares its `input_def`; the host validates the authored input against it.
- `registerPluginUnitSchema` rejects an **EMPTY** schema **unconditionally** (the `len(InputDefs) > 0` carve-out is deleted in the charly leg).

Edited at its owning `skill:` entity (`plugin-skill` in `layer-charly-internals/charly.yml`), never the generated `SKILL.md` — per the marketplace's own "Edit the OWNING candy repo's `skill:` entity, then regenerate" rule.
