# 2026.281.1019 — docs(git-workflow): assert the body edit landed, then read the live body back

## Summary

Adds **one rule** to the `git-workflow` skill's "BEFORE ANY UPDATE PUSH" section, placed directly beside
the read-then-write invariant it belongs with, together with the two habits that close the same class
from the other end.

**The failure mode it kills** — measured four times on 2026-10-08, across three PRs and three
repositories: a PR body is rewritten by script far more often than by hand, and that rewrite fails
**silently**. A `str.replace`/`sed` whose anchor stopped matching (a renamed heading, a reflowed line, a
re-quoted string) returns the input UNCHANGED and exits 0, so the script reports success while the prose
keeps describing an edit the artefact never received — and the next `charly/pr-validator` verdict blocks
on evidence attributed to a head or a symbol that is not there. Concretely: `plugin-check#90` round 1
(three references to a `§2c` that did not exist), round 2 (§1's pasted unit output still naming
`TestKeepVenueAlways`, a symbol the head no longer defines), and the two adjacent bodies before it.

**What the rule says**, in the skill's own voice:

1. **Assert every insertion** — `assert s.count(anchor) == 1` (or an explicit `if anchor not in s: raise`)
   around EACH replacement, so a silent no-op cannot pass.
2. **Read the live body back** — `gh api repos/<o>/<r>/pulls/<n> --jq .body`, then grep it for a NAMED
   marker unique to each edit (a symbol, a line number, a section heading) BEFORE firing any re-run,
   because the validator reads the body GitHub is serving, not the file on disk.
3. **Two supporting habits**: the head SHA and the command go INSIDE every evidence fence
   (`# head <sha> (git rev-parse HEAD)` as the fence's first line), so a paste carries its own provenance
   rather than depending on the prose around it; and every deferred debt carries a **NUMBER** (an issue
   number, a run id, a count) rather than a phrase like "later", so the record says what is owed and to
   whom.

**Where it lives.** The owning entity is `git-workflow-skill` in this repo's `charly.yml` (line 3803,
`skill: name: git-workflow`, `family: internals`). The marketplace corpus
(`opencharly/marketplace`, `internals/skills/git-workflow/SKILL.md`) is that entity's **generated
projection**, so this PR is the **producer half**: merge → tag → the marketplace regeneration PR bumps
its pin and carries the regenerated corpus in the same change (marketplace `README.md:54`).
