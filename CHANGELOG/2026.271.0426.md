**The three field-learned watcher requirements — plus the stale-fire guard**, all encoded as defaults in the tools, not left as tips:

1. **Silence is an ALARM.** A blocked item with no pushes emits **no validator runs and no events**, so an event-only watcher is blind to the worst case. Every watcher carries a per-item stall layer; `gh_watch.sh`'s `stall` is **on by default**. *The events tell you when something HAPPENED; the stall alarm tells you when something SHOULD have and did not.*
2. **Watch the OUTCOME, not every event.** The default event set is the terminal outcomes (`merged`,`closed`) **plus the `stall` alarm**; `comment`/`verdict` are opt-in, to avoid waking on every comment of an actively-iterating owner.
3. **Liveness ≠ progress.** Progress is judged by **artifacts** — a pushed branch, a new commit, an opened PR, a merged tag — never a session heartbeat or "still investigating". The stall alarm keys on the item's `updated_at`, so its silence is measured against artifacts, not activity.
4. **A "new" event must be genuinely NEWER than arm time — never a stale fire** (the guard that sits beside the three requirements). An **empty seed is UNKNOWN**, not "no prior run": a transient `gh` failure can leave it blank, and a naively-armed watcher then treats an OLD completed run as new (measured: a run from ~90 minutes earlier re-surfaced as fresh). On arm, capture the baseline AND the arm wall-clock; a `verdict` fires only when the run's `createdAt` is at/after arm time (the helper returns `createdEpoch`) or its id differs from a KNOWN prior; an empty baseline is adopted WITHOUT firing.

Fully generic: no org, repo, session, or date is baked in.

**The family is THREE watchers plus a shared helper library.** `pr_state_watch.sh`, `pr_watch_many.sh`, and `gh_watch.sh` are the three; `_watch_common.sh` is the shared library both new watchers source (usage extractor, uint check, event-membership test, newest-completed-run query) — it is not a fourth watcher.
