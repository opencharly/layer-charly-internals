# 2026.297.0301 — docs(skills): describe the `ellipsis` rule's positional form

## Summary

The `git-workflow` skill's `references/pre-validator-self-audit.md` described the org's body linter as failing a PR body on *"any ellipsis character inside a fence"*. That is the rule's OLD form. The linter's new form (**opencharly/marketplace#537**) classifies the character by **where it sits**, so a program that prints an ellipsis in its own output can have that output pasted into a body verbatim.

| file | what it carries |

| `.agents/skills/git-workflow/references/pre-validator-self-audit.md` | the AUTHORED sentence — the rule's new form |

The rule's three findings, and everything else it allows:

| finding | the position | what it is |
|---|---|---|
| `command` | the line is a `$ ` command line | the author's own typing, elided |
| `head` | the line is in the output of a head-bearing command in the same fence | the elision hides the head the `head` arm compares |
| `dropped` | the line's whole content is an ellipsis | a run of lines dropped from the paste |
| — | anything else | a program's own token, pasted verbatim |
