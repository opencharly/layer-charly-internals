# 2026.269.1446 — docs(git-workflow): correct the body-before-push rule (body precedes the trigger)

## Summary

Correct the `git-workflow` skill's **body-before-push** rule: it stated an
impossible order (which forced empty "re-freeze" commits) and a trigger list
that omitted `edited`. All occurrences are swept to one authoritative statement.

### RCA (8-step, R1)

**Unexpected.** The rule told authors to "push source → compute the final head +
diff-stats → write the body". The head it says to compute only exists **after**
the push, yet the body must exist at the moment the push triggers the validator
— so authors pushed an empty commit just to fire a new run.

**Mechanism / root cause.**
1. A commit's SHA is **content-addressed** — `git rev-parse HEAD` yields the SHA
   the push will publish, before pushing — so the body is always written first.
2. The trigger list was `[opened, synchronize, reopened, ready_for_review]` with
   **no `edited`**, so a body-only fix started no run (hence the empty commit).

**Blast radius.** Every contributor following the skill.

### Fix (all three sites swept — R5 claim-keyed)

The file previously stated BOTH "`edited` IS a trigger" and "`edited` is NOT a
trigger" in one commit; this corrects every site to the single truth established
by **opencharly/.github#119** (the org required workflow now fires on
`pull_request: edited`):

- **"THE BODY-BEFORE-PUSH RULE"** — real order: commit → compute the known SHA +
  diff-stats → write the body → push; a body-only fix re-runs via `gh pr edit`
  (the `edited` trigger), **no empty commit**.
- **"FINISH THE BODY BEFORE THE TRIGGER"** invariant — trigger list now includes
  `edited`; the empty commit is removed as a remedy.
- **Body-only-BLOCK recovery** paragraph and the **POISON-state remedies** —
  replaced "push a NEW commit / empty re-freeze" with the capability-free
  **`gh run rerun <run-id>`**: a re-run reuses the same `GITHUB_SHA` and updates
  THAT run's check run in place (no duplicate same-name check run), keeping the
  gate `checks: write`-free (honoring the org's T4 stance).
