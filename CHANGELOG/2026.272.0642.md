# 2026.272.0642 — docs(agents): add the rotate-on-stall mechanism (behind the umbrella 'Subagent lifecycle' rule)

## Summary

Adds the **rotate-on-stall** mechanism to the `agents` skill's
`references/hooks-and-lifecycle.md` content (the `agents-skill` entity in
`charly.yml`) — the mechanism behind the umbrella `AGENTS.md` rule **"Subagent
lifecycle — one task per worker; rotate, never re-task"**
(`opencharly/opencharly#305`). That rule points here for MECHANISM DETAIL, but
this reference covered only **cross-task** reuse (finished worker → new task),
not the failure that motivated the rule: **repeatedly re-briefing a stalled
session**.

New `### Rotate on stall — stop a stalled session, spawn a fresh one`
subsection, adding:

- **The hard trigger** — no ARTIFACT after **two re-briefs**, or **~50 messages
  without a produced artifact** → STOP it and spawn a FRESH subagent with a
  clean brief; do not append a third correction.
- **Why re-tasking a stalled session fails** — the measured **7-hour /
  351-message** session that produced **no artifact** on a few-file change,
  while a **fresh** session with the same brief produced it directly.
- **Artifacts, never liveness** — an idle signal, a heartbeat, or "still
  working" is NOT progress; act only on a changed artifact.
- **The distinction from legitimate continue-same-task** — a CHANGES-REQUESTED
  fix round / rebase round is reuse; re-briefing a session that has stalled
  **without producing** is rotation.
- **The orchestrator's duty** — monitor by artifact and rotate on the trigger,
  mirroring the existing "orchestrator's bidirectional verification duty".
- **A cross-reference to the AGENTS.md rule** so the two cannot drift (one
  canonical statement in AGENTS.md, the mechanism here).

Discoverability: the entry `SKILL.md` Index row for
`references/hooks-and-lifecycle.md` now names **rotate-on-stall**, and the
reference's opening "Owns the …" sentence names it too. No new cross-reference
target is introduced (the `orchestration-model.md` reference already exists and
is linked relatively), so `charly docs generate` resolution is unaffected.

Closes #61.
