# 2026.275.0248 — docs(git-workflow): re-run the org-required gate through the REST API; a re-run is a new attempt

## Summary

The git-workflow skill (and repo-setup) prescribed **`gh run rerun <run-id>`** as **the** body-only-fix path, which re-runs the required `validate / validate` gate on the same head. That command cannot re-run the org-required validator. The skill also claimed that a re-run "updates THAT run's check run IN PLACE — no duplicate", which is false too.

This PR rewrites every occurrence in the skill source (`charly.yml`). The four surfaces are:
1. the SKILL body's "THE BODY-BEFORE-PUSH RULE" and its POISON paragraph;
2. the "FINISH THE BODY BEFORE THE PUSH" invariant;
3. the `validator-and-calver` reference (the body-only BLOCK fix and the POISON remedy);
4. the repo-setup step 4.

The new text prescribes `gh api -X POST repos/<owner>/<repo>/actions/runs/<run-id>/rerun` and states the measured behaviour. It also replaces an earlier "MEASURED on opencharly/sdk#301: exactly ONE check run" claim, which was a filter artifact (see below).

Relates to #71 (the remaining scope: marketplace regeneration, the governance rows in opencharly/.github#156, and the upstream gh issue).
