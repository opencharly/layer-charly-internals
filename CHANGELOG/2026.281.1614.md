> **Absence of evidence in a TRUNCATED run is not evidence of absence - check that the run got far enough to look.**

A red gate that fails in **setup** cannot report a finding that its **analysis** step would have produced. So *"the run shows no finding"* from such a run says nothing about the code.

**Measured four times in one session:**

1. a step that died building its own tool;
2. a provider outage that stopped the engine producing a review;
3. a cold module cache that stopped the analysis step reaching the module;
4. a cache-restore failure that made a typecheck report a *missing sum* for a module whose sum was present.

Each was read initially as the gate being red for reasons unrelated to the change, and **each was resolved only by reproducing the step's own order** - generate, then analyse - rather than the part that happened to finish.

> **Before concluding a failure is not yours, establish that the failing run reached the stage that judges your change.**
