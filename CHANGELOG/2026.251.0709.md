# 2026.251.0709 — docs(skill): git-workflow validator re-trigger + body-evidence mechanics (measured)

## Summary

The `git-workflow` skill entity gains a MEASURED operational section: **Validator re-trigger + PR-body evidence mechanics** — five lessons verified live while driving the eval-omarchy #38 wave through the org pr-validator:

1. An empty commit does NOT re-trigger `pr-validator` (the pull_request workflow ignores no-diff pushes) — use a REAL commit or `workflow_dispatch -f pr-number=<N>`.
2. A `workflow_dispatch` without `--ref` runs on the DEFAULT branch — its green check registers on the default-branch commit, not the PR head, and auto-merge can never fire; dispatch with `--ref <pr-branch>`.
3. Dispatch ONCE per head — duplicates on the same head leave failed same-name check runs that GitHub's merge evaluation can pick, keeping `mergeable_state: blocked` despite a PASS.
4. The PR body must match a FROZEN head — commit SHAs/diff-stats are mutable until the branch stops moving; rebase/amend after writing the body guarantees a Rule-4 body-truthfulness BLOCK. Freeze → write body → push once; fixes = one atomic commit+body+push batch.
5. `gh_pr_status` `mode:'watch'` can act as a one-shot in some environments — bounded `check` poll loops as the fallback.
