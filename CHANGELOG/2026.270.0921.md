# 2026.270.0921 — docs(internals): issue-first coordination — search/file/claim issues + check issue & PR comments before every push

## Summary

Extends the `git-workflow` cross-session coordination guidance with an **issue-first**
protocol and broadens the mandatory pre-push check to cover issues:

1. **B2b — search first; file and own an issue.** Before any non-trivial work (and before
   filing anything), search the org for an existing issue/PR (`gh search issues/prs`,
   `gh issue list -S`) and ADD to it rather than duplicating; if none exists, file ONE
   proper issue (title/problem/evidence/scope) and reference it from the PR
   (`Closes #N` / `relates to #N`).
2. **B2b — the issue is the coordination point.** Check the issue's owner and CLAIM it
   (comment + assign) BEFORE branching; if another session owns it, coordinate on the
   thread (take a slice / ask status / hand off) instead of opening a competing PR. Use
   issue comments for every cross-session move (claim, block, hand-off, duplicate,
   supersede).
3. **B2b — before EVERY push, read the new comments on the PR AND on every related
   issue**, and act on each.
4. **New invariant** — search existing issues/PRs before starting; file one proper issue
   if none; claim it before branching.
5. **The "BEFORE ANY UPDATE PUSH" invariant** now also requires reading the latest
   comments/state of every issue the PR closes/relates to.
