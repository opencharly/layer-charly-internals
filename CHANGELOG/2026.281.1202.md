# 2026.281.1202 — docs(git-workflow): a branch update invalidates every tree-pinned fence

## Summary

The fifth body-evidence bullet, beside the four already merged (`#92`, `#93`, `#95`):

> **After ANY branch update, every tree-pinned fence in the body is invalidated — re-take the evidence, do not re-label it.**

A branch update (`gh pr update-branch`) rewrites the head **by definition**, so a fence that names the commit it ran on now names a commit that is no longer the head. **Measured three times in one evening** — `charly#846`, `charly#849` and `charly#843` each lost a review round to exactly this — and in each case the reviewer's closing argument was the body's *own* standard: a count is only comparable to another count from the same tree.

The cure is the one the staged discharges already use: rebuild on the head, run the gate on that tree, paste **that run's** own attribution, and delete the bridge rather than re-arguing tree equivalence or artifact identity. `charly#843`'s update-invariance covered the **state**; this covers the **evidence**.

It sits with the other four because it is the same family: assert every insertion · a fence that names its head is self-attributing but not self-verifying · a claim about the object is only as good as the string you hand the probe · presence checks catch missing fixes, only an absence check catches leftover ones.
