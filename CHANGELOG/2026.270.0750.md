## Summary

Follow-up to the merged `layer-charly-internals#28` (the `repo-setup` skill + B8 +
CalVer fix). This PR adds the coordination/mandate prose that was authored after #28 had
already auto-merged, so it is a fresh PR on top of current `origin/main`. Only
`charly.yml` changes — `skill:` documentation prose:

1. **`git-workflow` B2b — cross-session coordination.** When ANOTHER SESSION'S PR blocks
   you, the ONE channel is a **PR comment on the PR that owns the blocking file** (or a new
   issue naming it), actionable (your slug + the exact file/gitlink/pin + what unblocks you
   + evidence); then STOP and ask the operator. Never edit their artifact, work around it,
   or force-land. A fresh `pr-validator` weighs the comment thread (comment intake).
2. **A mandatory "BEFORE ANY UPDATE PUSH" invariant** — before ANY push that updates an
   existing PR (a fix commit, a body edit, or `gh pr update-branch`): ALWAYS read the PR's
   LATEST comments + validation results AND ALWAYS write/update the PR body for the head
   being published. Pairs the existing FINISH-THE-BODY-BEFORE-THE-PUSH rule with the read
   step in ONE invariant (the validator re-reviews diff + body + full live thread each run).
3. **A mandatory precondition on the skill itself** — reading the dispatched skills
   (`git-workflow` in particular) is a hard, **non-optional precondition before ANY code
   change**; a git/PR action taken before loading them is an R0 violation and not landable.
4. Reference Index row updated to name B2b.
