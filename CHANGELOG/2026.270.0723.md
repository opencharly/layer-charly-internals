## Summary

Adds clear, non-ambiguous guidance to the `charly-internals` skill family. Only
`charly.yml` changes — new/changed `skill:` **documentation prose** (no packages, steps,
services, plan, behavior, or pins):

1. **New `repo-setup` skill** (`repo-setup-skill`) — how the opencharly org and
   `opencharly/.github` (dotgithub) configuration drive every repo: the ONE org ruleset,
   the org-required `charly/pr-validator` workflow, native auto-merge (squash),
   `tag-on-merge` CalVer, and the per-repo settings (`allow_auto_merge`,
   `delete_branch_on_merge`). Includes a NEW-repo checklist and the measured gap that

2. **`git-workflow` B8** — the after-merge close-out checklist: confirm merged, remove
   ONLY your own worktree, delete the local branch ONLY if `--merged`, fast-forward
   `main`, then catch up the umbrella via `task sync` + `task verify` + PR. States the ONE
   worktree-location difference (standalone `.claude/worktrees/<slug>/` vs umbrella
   `.worktrees/<slug>/<repo>/`) and the rule that submodule pins are GITLINKS whose
   checkouts stay DETACHED.
3. **CalVer correction** — the proxy-consumed root modules are `sdk`, `spec`, AND
   `plugin-gh` (not `sdk` alone); fixed at both surfaces that carried the stale claim
   (`cutover-policy` and the `git-workflow` CalVer reference).
4. **Cross-reference** — `git-workflow` now points at `/charly-internals:repo-setup`.

**Validator round 1 fix (B9/R4a):** the reader-facing commands in the new prose now use
the bare `charly task sync` / `charly task verify` (no repo-relative
