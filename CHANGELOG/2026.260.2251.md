# 2026.260.2251 — docs(git-workflow): a generated evidence fence must be able to fail

## Summary of changes

Codifies an insight proven live during this session's generator work (the `sync.yml` /
`refresh.yml` body emitters): **a generated evidence fence must be able to fail.** A workflow that
splices a foreign file into an evidence fence with `sed -n '/<anchor1>/,/<anchor2>/p'` prints
**nothing** when either anchor moves, so the fence ships EMPTY beneath prose that still asserts the
gate — a guard that cannot fail, the exact class the reference's "A guard that cannot fail is worse
than no guard" section names. The remedy the generators now use, documented here:

- capture the splice into a variable and refuse an empty result with an explicit ERROR marker;
- derive a zero-warning / `resolved` claim from the producing log's own summary line, failing loud
  when that line is absent, rather than defaulting to the optimistic value.
