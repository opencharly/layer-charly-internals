# 2026.280.0016 — docs(skills): a skill `triggers:` addition is CONFIG — its proof is the emitted row

## Summary

Upstream the change-class lesson a fresh `pr-validator` BLOCK surfaced on
opencharly/pod-dsh#14 into the `skills` skill. Fixes opencharly/layer-charly-internals#86.

### The gap

The `skills` skill covered *when* to update skills and how the dispatcher corpus is
delivered, but not the change-class consequence of adding a `triggers:` field. A
`triggers:` value is **not** prose: `emit_dispatcher.go` consumes it to emit exactly one
`DISPATCHER.md` row per triggers-bearing skill:

```go
if s.Type == "agent" || len(s.Triggers) == 0 {
    continue
}
```

A PR that only adds `triggers:` therefore alters a GENERATED artifact — it is a **config**
change, so `documentation reviewed` does not apply; and its proof is the emitted row, not
`charly box validate` (a structure check). A1/R10 forbid deferring the effect to the
nightly refresh bot.

### The fix

A new subsection under "Skill Dispatchers":

- `triggers:` is config that emits a generated row (not docs-only);
- the gate is the generator run + pasted `DISPATCHER.md` rows;
- when the owning repo's marketplace pin is OLDER than the branch (the common case for an
  unmerged skill change), generate from a minimal root carrying the exact changed entities
  — `CHARLY_REPO_OVERRIDE` cannot substitute a directly-pinned repo (the separate defect
  opencharly/opencharly#387).
