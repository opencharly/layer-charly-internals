# 2026.297.0850 — docs(skills): read the pushed range's trailers before the push

## Summary

The `git-workflow` skill's pre-validator self-audit had no arm that read the **commits**
a branch is about to push. The body linter reads the BODY's last line, and the org
rulebook's *AI Attribution* section says every AI-authored commit ends with an
`Assisted-by:` trailer — but nothing joined the two, so a trailer-less commit could sit
below the head while every control stayed green.

**Measured:** the umbrella PR `opencharly/opencharly#591`'s published branch
(`feat/light-init`) carried **three** merge commits with no trailer, one per review
round's catch-up merge, and the gap surfaced only when the history was re-read by hand
(opencharly/opencharly#613). The rate, not the three, is the defect: nothing read the
pushed range, so the gap regenerated every round. (PR #591 was later auto-closed and
superseded by #622; its branch stayed published, and the range below is read from that
published branch.)

**What this changes.** One new preflight step, 11, in
`.agents/skills/git-workflow/references/pre-validator-self-audit.md`: read the pushed
range's trailers, and resolve every commit the read names before the push.

| file | what it carries |
|---|---|
| `.agents/skills/git-workflow/references/pre-validator-self-audit.md` | preflight step 11 — the read of the pushed range's trailers, with the command, the base the range starts from, the one exemption, and what a still-local commit does about it |

**Round 2 — the validator's two BLOCK findings, fixed here.** The first round of this
PR was BLOCKed on two points, and both are fixed in the diff above:

1. **The GREEN half proved a different commit than the one being pushed.** It ran the
   arm's own pipeline over `origin/main..e83c84b` — a *published* range — while the
   body described head `60f09ff`. The head's own trailer status was therefore
   unverified. The GREEN half below is now run over `origin/main..HEAD` of **this**
   branch, on the head this body describes, and the range's own trailer counts are
   pasted beside it.
2. **The step's range placeholder was ambiguous, and read literally it defeated the
   step's own purpose.** The step said `origin/<branch>..HEAD`; read as the pushed
   FEATURE branch, that is only the *unpushed* commits, and it would never surface the
   published gaps the step is about. The range is now the PR's **BASE** branch's head
   to this branch's head — `origin/<base>..HEAD`, `<base>` named as the branch the PR
   merges into — which covers every commit the branch contributes, including the
   catch-up merges it pulls in from the base. The step also says to run it over **your
   own head, over that range**: a range you chose yourself proves a different range's
   commits.

The RULE the arm applies is not restated here: this repo's `AGENTS.md` forbids
restating the rulebook's rules, and the umbrella owns them. The rule line **landed** in
opencharly/opencharly#670 (merged `92564bda`, tag `v2026.297.0842`) — one paragraph in
the *AI Attribution* section saying that a merge commit is judged by its **message**,
not by its content — and the arm points at that section. It landed before this PR, so
the arm never ships against a rule that does not exist.

This is the **PRODUCER** leg of the corpus chain the finding names:
`layer-charly-internals` (this arm) → `marketplace` (regenerate the corpus projection,
which carries the same file) → `docs` → the umbrella's `layer-charly-internals` and
`marketplace` gitlinks.
