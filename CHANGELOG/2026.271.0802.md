# 2026.271.0802 — docs(skill): point the generate-source emitter caches at /var/cache/charly (sdk#279)

## Summary of changes

Docs-only correction (R1/R5): the `generate-source` skill text still documented the
SDK emitter's build caches at the old `/tmp` paths. As of `opencharly/sdk#279`
(tagged `v0.2026270.1024`, pinned by `opencharly/charly#711`) the emitter roots
them under `/var/cache/charly/...`, so the skill must describe current behaviour.

- `charly.yml` (the `generate-source-skill` entity):
  - the build-cache table rows for `command:` (non-root), `download:`, and the npm
    builder stage → `/var/cache/charly/{npm-cache,downloads}`;
  - the `EmitDownload` emit-description row + the inline `download:` example;
  - **the note that annotated those rows** — it claimed *"All non-root cache mounts
    use flat `/tmp/<tool>-cache` paths to avoid buildah permission issues with nested
    paths"*, which the edited rows now contradict. Rewritten to the real mechanism:
    ownership avoids the permission problem (a non-root cache mount is uid/gid-OWNED,
    `buildkit.OwnedCacheMount`), the vocabulary stage caches keep flat `/tmp` roots,
    and the two emitter-level caches moved to nested `/var/cache/charly/...`.
