# 2026.270.1546 — docs(internals): formalize agent identity footer + the coordination verb grammar (git-workflow B2b)

## Summary

Formalize how agents identify themselves and coordinate through GitHub comments.
Sessions on this host share **one GitHub account**, so the comment author cannot tell
two agents apart — identity and authority move to explicit, greppable fields:

- **Identity is TWO lines** — the `Assisted-by` trailer, then a separate
  `*Agent: `<slug>` · session `<ses_…>`*` line AFTER it. The slug is never appended.
- **Optional by default; MANDATORY on the trigger** — two or more agents on one
  issue/PR, OR a blocking dependency (`BLOCKS`/`UNBLOCKS` in play).
- **Authority in a closed verb grammar** — a coordination comment's first non-blank
  line is one of `CLAIM` · `OWNING` · `HANDING OVER` · `TAKING OVER` · `BLOCKS` ·
  `UNBLOCKS` · `STATUS` · `RESOLVED`, then sharp GitHub Markdown.
- **Same-account authority** — the footer slug is authoritative, not the GitHub
  author; the latest `OWNING`/`TAKING OVER` for a scope wins; you never push to another
  slug's claimed branch without a `HANDING OVER`, a `TAKING OVER` naming your authority,
  or operator sign-off.
- **Takeover window** — `TAKING OVER` cites `authority: hand-off | operator |
  window-expired`, posted BEFORE any push; the window runs on `charly/pr-validator` run
  COMPLETION, never on session activity (a looping agent never falls quiet; a peer
  waiting on the validator is not stalled).
- **Delegation ≠ impersonation** — an agent never impersonates the operator, but a
  sign-off posted at the operator's explicit direction, labelled delegated and carrying
  the agent's own footer, IS valid (matches the amended `AI_REVIEW_PROMPT`).
