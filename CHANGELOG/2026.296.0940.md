# 2026.296.0940 — docs(internals): a wave holds the umbrella's index, and a contended stage is not a lost pin

Closes #137

## Summary

**The finding.** The umbrella's pinning guidance already told an operator to keep their
hands off a worktree while a mutating `sync` runs — but only for the *submodule's*
index. It never said that a wave holds the **superproject's** index, for the minutes it
rolls the submodules, and that a plain `git status` in that same worktree takes the
same index lock for an instant. So the wave's own `git add` can lose the race, and the
guidance gave the operator no reason to keep their hands off.

**What this change adds.** One paragraph — twenty lines — in the file that owns the
umbrella mechanics, `.agents/skills/git-workflow/references/umbrella-mechanics.md`,
beside the sentence that already says *never run a mutating `sync` concurrently with
anything else*. It says three things:

- **The mechanism.** The bump stages each advanced path with a `git add` in the
  superproject, and that `git add` takes the worktree's index lock; a concurrent
  `git status` in the SAME worktree takes the same lock for an instant, so the wave's
  own `git add` can lose the race. The wave is minutes long, so the window is wide.
- **The rule.** While a wave runs, run no other git command in that worktree; and
  after it, ask the currency question (`charly task pins --param MODE=currency`), which
  names every pin that is not at the ref its intent names.
- **The distinction that keeps the claim true.** A contended path is a path the wave
  could not **STAGE**, and whether that cost a **PIN VALUE** is a *second* question:
  the path may have been at the ref it already serves. The wave's own report cannot
  answer it, and a gate that reads CONSISTENCY cannot either — the contract that
  answers it is in `references/pin-intent-and-currency.md`.

It also says where the fix does **not** belong: in the verb. A bounded lock-wait is a
sleep and a lock-retry is a blind retry, and both are forbidden, so the guidance does
not ask the verb to change. The verb's behaviour is the intended one — it names every
contended path, it does not abort the walk, and it reports failure rather than success.

**The dated reading.** One measurement, dated 2026-10-23, from the umbrella wave
`opencharly/opencharly#623`: a wave's staging lost the index lock to a concurrent
`git status` in its own worktree, the paths the wave named were already at the refs
they serve, and the currency report — not the wave's own report — was what said so.

**No count of pins, and no claim the tree contradicts.** The paragraph carries no count
of pins at all, and it distinguishes a contended *stage* from a *pin value*, so the
rule it states holds on the tree the wave actually produced. That distinction is the one
the umbrella wave's own final tree forced: the contended paths were already at the refs
they serve, so the failed stage cost a stage. A rule that said otherwise would have been
a false claim about the org's own tree.

**The corpus is GENERATED.** The marketplace copy is not edited here. The corpus leg
belongs to `opencharly/marketplace`, in the ordinary producer-first order.
