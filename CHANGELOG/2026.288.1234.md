# 2026.288.1234 — docs(skill)!: evidence discipline — a claim about an artefact you have not read

## Summary

Adds one reference subsection to the `git-workflow` skill's `evidence-and-freshness.md`:
**"A claim about an artefact you have not read"** — six rules earned in a single session on the
BuildKit/OCI distribution wave, all six being the same act: asserting something ABOUT an artefact
instead of reading it.

- **A copied file's prose is not yours.** A dispatcher file copied byte-for-byte into 27 repositories
  carried the ORIGINAL repo's RCA in its comment block ("measured in this repo across 8 merges and 17
  schedule runs", "PR #3's tag landed 4+ hours late"). The bytes were identical; the *claims* were
  false in every copy.
- **A truncated hash is not identity.** A 16-character `sha256` prefix pasted as proof of byte-identity
  establishes a prefix and nothing more.
- **An empty stream has a hash.** `e3b0c44298fc…` is the digest of NOTHING, and it appears whenever a
  probe 404s and its empty output reaches `sha256sum`.
- **Read the whole artefact, not the parts your rule cites.** A rulebook answer declared the
  `wait-for-merge` poll loop "not in anything added here" — written from memory, having read the file's
  comment and its triggers and never its `jobs:`. The loop was in the diff.
- **Read the diff GLOBALLY, and account for every `-` line.** For a narrative file, deletion is the
  dangerous direction: an addition is visible in the result, a deletion only in the diff.
- **Never format the data you are about to parse.** Indenting a file for display shifted every field and
  a later `read` bound the wrong columns — silently.

The cost of the remedy is one tool call; the measured alternative was nine BLOCKs and two full passes
across 25 pull requests.
