# 2026.243.0925 — docs(skills): M3 - validator per-HEAD re-review + workflow_dispatch --ref in git-workflow

## Summary

M3 memory-to-skill migration: two proven landing-mechanics lessons the audit hit live land in the git-workflow skill's invariants.

1. **Validator re-review is per-HEAD** — body-only edits do not re-trigger the org validator (it reviews the head SHA); an evidentiary fix needs a NEW commit (`git commit --allow-empty` with a docs message is the standard append-only re-trigger). Corollary: an EMPTY-diff PR (base already has the change — branched from a stale snapshot) is a no-op — close it; always `git fetch origin main` + diff against current main before finalizing.
2. **`workflow_dispatch` defaults to the DEFAULT BRANCH** — `gh workflow run <wf> --ref <branch>` is required to dispatch on a PR head; a dispatch landing on main contributes no required-check run.

Both were experienced repeatedly in the 2026-08-31 audit session (three PR-re-validation cycles + one duplicate PR), now codified where the git-workflow skill already carries the append-a-commit invariant.
