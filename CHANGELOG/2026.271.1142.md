**RCA of the warning this replaces (R1).** An earlier local run used the umbrella dev/worktree binary and emitted:

```
WARNING: charly is a dev/worktree build (not installed at /usr/bin or /usr/local/bin);
NOT loading the installed package's plugins from /usr/lib/charly/plugins ...
```

Root cause: this host has the `charly` system package installed (`/usr/bin/charly`, owning `/usr/lib/charly/plugins`). `bakedPluginDirs` (`charly/plugin_loader.go`) deliberately drops the FHS plugin path with a one-time notice when the running binary is a dev/worktree build (issue #328), so it never silently loads plugins built against a different charly version. The notice is therefore an artifact of the local host, **not** a manifest warning. The supported AS-IF-UNPACKAGED route (`CHARLY_PLUGIN_ONLY=1`) reproduces the CI environment exactly and drops the FHS path without the notice, and running the pinned release binary produces the genuinely zero-warning output above.
