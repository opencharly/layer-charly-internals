# 2026.267.2049 — docs(skill): document the validator INCONCLUSIVE (verdict-less) class

## Summary

Document the validator's **INCONCLUSIVE (verdict-less)** terminal state in the `git-workflow` skill. The skill covered PASS, a verdict BLOCK, and the POISON state — but not the state the gate emits when its review engine produces **no `Verdict:` line at all**, so an agent could mistake it for a code finding, or re-dispatch the same head against a stale engine.

**One added section — "The INCONCLUSIVE (verdict-less) class — the gate ran but produced no verdict".** The required check stays RED on purpose, but it is **not** a finding about the diff. The section gives:

- the exact comment header the gate posts (`## validator INCONCLUSIVE — no review verdict was produced (not a BLOCK; no code finding)`) and the rule to read its `Diagnostics` tail FIRST, then classify the cause;
- the **two root causes**, told apart by the diagnostics:
  - **stale-engine** — `turn 1: N tool call(s)` → `turn 2: final content len=0`: the `plugin-review` welded into the charly binary the gate ran is older than the fix (the org pins `vars.CHARLY_VERSION`; a self-hosted image that bakes an older `charly` used to short-circuit it). The pin enforcement that closes this is `opencharly/.github#115`. The cause is the RUNNER ENVIRONMENT, not the diff → escalate to the operator;
  - **provider/endpoint** — `inconclusive: … provider did not respond / attempt timed out` or an HTTP/stall marker: owned by the gate's `AI_REVIEW_*` provider configuration → escalate to the operator, who owns that configuration;
- the distinction that matters: a real **BLOCK** has `## Review — BLOCK` + a `### Blocks` list to fix; an INCONCLUSIVE has neither and must NOT be treated as a finding (R1 misdiagnosis);
- **never merge around the red check** — an INCONCLUSIVE is an environment/provider condition to fix or escalate, and the only merge under a red required check is an operator-issued override decision, taken by the operator on evidence THEY accept — never an agent's call, and never a documented standing procedure.

No override recipe is added: authoring a "bypass the validator" procedure is not the skill's to authorise, and the gate can never be landed around.
