# 2026.281.0831 — docs(agents): add the goal-budget and watcher-waiting rules to the agents skill

## Summary

Adds two rules to the `agents` skill entity in this repo — the skill's authoritative source, from which the marketplace's `internals/skills/agents/SKILL.md` is projected:

1. **The goal round budget** — measured from the DSH source: `dsh-goal`'s `Config.defaultMaxGoalRounds` is **256**, and `dsh-goal-round-driver` blocks **hard** the moment `roundsStarted >= maxGoalRounds` (`{code: "round-limit"}`, phase `blocked`, goal **disarmed**), with **no warning phase**. There is no project-level patch file, so the only knobs are the per-goal parameter and the host profile's default. **RCA (2026-10-08, this session's own campaign):** a 76-issue, multi-cluster objective was created with `max_goal_rounds: 40` — **6.4× below the harness default** — needing roughly 150–250 owner turns, so it hit `round-limit` and **disarmed mid-flight with the operator never asked**. The work survived only because the ledger and hand-over were current. Rules: size the cap to the work (one owner turn per PR per verdict round, plus one bed per runtime change); never go below the default without a stated reason; and at ~80% of budget with work remaining, **STOP and ask the operator** with options rather than narrating an ending. The umbrella states this as `AGENTS.md` Part II rule 10; this entity carries the HOW.

2. **Wait with the watchers, never with rounds** — goal rounds are a **budget, not a clock**. *Measured:* a validator window of 2–10 minutes spanned several goal rounds while the environment clock advanced **8 seconds in one round**. Arm the org's own watcher as a **background job**, because the harness notifies the session when a background command finishes — so the watcher's exit **is** the wake (the watcher is armed as a background job whose exit IS the wake; its **portable `charly` command is not yet available**, which is filed as `opencharly/charly#837`, so the rule is stated without prescribing a checkout-relative path). One watcher per scope; a DELTA fire (`verdict`/`comment`) arms its own successor while a STATE fire (`merged`/`closed`/`stall`) is terminal and must not be re-armed; re-arm the harness job to keep receiving notifications; include **every** blocked dependency, because the un-watched one is the one that arrives late. Never hand-roll a poll loop.
