# 2026.296.0029 — docs(internals): the umbrella's clone shape and the currency mode that already answers

## Summary

The `git-workflow` family's umbrella guidance had drifted from what the umbrella's own
task surface actually does. One cutover corrects **five files**, because a claim-keyed
sweep found the same false sentence in three of them.

The false sentence: the guidance said the `currency` mode of the pin verb was **not in a
released binary** and that a reader "must MEASURE" the question by hand, building a
`<path>: <recorded gitlink> vs <remote default-branch HEAD>` table. It is **in** the
released binary, and the umbrella's own task surface reaches it:
`charly task pins --param MODE=currency` answers the question and names the states. The
hand-built table was a second implementation of a verb that already answers it, and it
drifts.

The R5 sweeps are claim-keyed, and each claim carries the same instrument run against a

**The instrument.** A line-oriented `git grep` reads one line at a time, so a claim whose
words are split across a line break is invisible to it: the sweep is green while the
claim sits in the file. This instrument folds each file's content to **one** line before
the pattern is applied, so the pattern sees the file's text, not the file's line breaks.
Its file list is NUL-delimited, so a path containing a space is one path and not two:

```sh
#!/usr/bin/env bash
# A claim-keyed sweep that sees a claim even when it spans a LINE BREAK.
#
# A line-oriented `git grep` reads one line at a time, so a claim whose words are
# split across a line break is invisible to it: the sweep is green while the
# claim sits in the file, which is a control in name only. This instrument folds
# each file's content to ONE line before the pattern is applied, so the pattern
# sees the file's text, not the file's line breaks.
#
# The file list is NUL-delimited (`find -print0` + `read -d ''`), so a path that
# contains a space is ONE path and not two — an unquoted `$(find .)` in a `for`
# loop splits it, and a sweep that walks a different file list than it claims to
# is a control in name only.
#
# usage: producer-sweep.sh <root> <pattern>
#   exit 0 = no match anywhere under <root>
#   exit 1 = at least one match (each is named)
set -u
root=${1:?usage: producer-sweep.sh <root> <pattern>}
pat=${2:?usage: producer-sweep.sh <root> <pattern>}
hits=0
while IFS= read -r -d '' f; do
  if tr '\n' ' ' <"$root/$f" | grep -qE "$pat"; then
    hits=$((hits + 1))
    echo "MATCH: ${f#./}"
  fi
done < <(cd "$root" && find . -type f -not -path './.git' -not -path './.git/*' -print0 | sort -z)
echo "hits=$hits"
[ "$hits" -eq 0 ]
```

### The count-behind sweep — the class, not one spelling of it

The third sweep above is keyed on the **digit** form `N pins behind`. The validator found
the word form sitting in the guidance while that key was green, so the key is now the
**class**: a number, in digit or word form, qualifying a pin/submodule/repo/gitlink
subject, together with a "behind / stale / not current" assertion. Each hit is
**classified** by whether its **own sentence** carries a date — a dated sentence is a
dated reading (printed with its date), an undated one is a bare point estimate and a
finding. The date has to be in the claim's own sentence, because a date that belongs to
a different claim is not this claim's date; that is the property the control exercises,
since `SKILL.md` carries another date two sentences away from the count.

**This is the instrument, in full:**

```sh
#!/usr/bin/env bash
# count-behind-sweep.sh — the ABSENCE instrument for the "a COUNT of pins/submodules
# behind their remotes" class, with the DATE classification attached.
#
# WHY IT HAS THIS SHAPE (a control that has never fired is a control in name only —
# the digit-only `git grep -nE '[0-9]+ pins behind'` was green while the word-form
# claim sat in the file, so the body's "proves the absence" was true of the
# instrument and false of the guidance):
#
#   1. The file is FOLDED — every newline becomes a space — before anything is
#      matched, so a claim that spans a LINE BREAK is seen wherever its words fall.
#   2. The class is matched as a SHAPE, not as one spelling. A sentence counts only
#      when it carries BOTH
#        (a) a COUNT FORM — a number, in digit or word form, that QUALIFIES a
#            pin/submodule/repo/gitlink subject: "25 pins", "429 submodule(s)",
#            "five of six", "14 of 429 pins"; and
#        (b) a "behind / stale / not current" assertion.
#      A digit-only key could not see "five of six `distro-*` were", and a loose
#      "a number somewhere plus the word stale" key fires on prose that counts
#      nothing, so the shape is deliberately the narrow one.
#   3. Each hit is CLASSIFIED by whether ITS OWN SENTENCE carries a date
#      (YYYY-MM-DD). A hit whose own sentence is dated is a DATED READING — a
#      survivor, printed with its date. A hit whose own sentence carries NO date is
#      a bare point estimate — the class the rule forbids — and is a FINDING.
#      The date must be in the CLAIM's own sentence: a date that belongs to a
#      different claim is not this claim's date, and the sentence is the unit that
#      says which is which.
#
# usage: count-behind-sweep.sh <root> [suffix]
#   <root>    the tree to sweep
#   [suffix]  the file suffix to sweep (default: .md)
#   exit 0 = every hit is a DATED reading (or there is no hit)
#   exit 1 = at least one UNDATED hit — the class the rule forbids
set -u
root=${1:?usage: count-behind-sweep.sh <root> [suffix]}
suffix=${2:-.md}
[ -d "$root" ] || { echo "count-behind-sweep: $root is not a directory" >&2; exit 2; }

out=$(mktemp)
find "$root" -type f -name "*$suffix" -not -path '*/.git/*' -print0 |
while IFS= read -r -d '' f; do
  awk -v FILE="${f#$root/}" '
    BEGIN {
      num = "([0-9]+|one|two|three|four|five|six|seven|eight|nine|ten|eleven|twelve)"
      # a COUNT FORM: a number that qualifies a pin/submodule/repo/gitlink subject
      form = "(" num " of (the )?" num "|" num " (pins?|submodules?|repos?|gitlinks?|checkouts?|distro-\\*))"
    }
    { text = text " " $0 }
    END {
      gsub(/[ \t]+/, " ", text)
      gsub(/([.!?]) +/, "\\1\x01", text)
      n = split(text, sents, "\x01")
      for (i = 1; i <= n; i++) {
        s = sents[i]
        if (s !~ /behind|stale|not current|not up to date/) continue
        if (s !~ /(^|[^A-Za-z0-9_-])(pins?|submodules?|repos?|gitlinks?|distro-\*|checkouts?)([^A-Za-z0-9_-]|$)/) continue
        if (!match(s, form)) continue
        counted = substr(s, RSTART, RLENGTH)
        dated = (s ~ /20[0-9][0-9]-[0-9][0-9]-[0-9][0-9]/) ? "DATED" : "UNDATED"
        d = (match(s, /20[0-9][0-9]-[0-9][0-9]-[0-9][0-9]/)) ? substr(s, RSTART, 10) : "-"
        gsub(/^\x01 /, "", s)
        printf "%s\t%s\t%s\t[%s] %s\n", dated, d, FILE, counted, substr(s, 1, 180)
      }
    }
  ' "$f"
done | sort >"$out"

cat "$out"
awk -F'\t' '
  $1 == "UNDATED" { u++ }
  END {
    printf "hits=%d undated=%d\n", NR, u + 0
    exit (u + 0 > 0) ? 1 : 0
  }' "$out"
rc=$?
rm -f "$out"
exit "$rc"
```
