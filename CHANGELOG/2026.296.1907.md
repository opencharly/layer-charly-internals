## Summary

Head `eb9c375c525ab26241049e3ed8a51da6acc5d208` — 1 file changed, 45 insertions(+), 29 deletions(-). The change is one prose file: `.agents/skills/git-workflow/references/umbrella-mechanics.md`, the `git-workflow` skill's umbrella-mechanics reference.

`charly task sync` — the verb that advances a pin — used to REFUSE a path with no checkout. The pin lives in the superproject's **index**, but the advance reached it through the **checkout**, so a path with no checkout had no tip to move and the run failed loud. A pin wave therefore needed the **FULL SET** — every repo materialized — to move one pin.

`opencharly/plugin-task#37` (PR #38, merged as `b5e24d2`, tagged `v2026.296.1852`) removes that cost at the root: the pin IS the index entry, so a path with **no checkout** is advanced **in the index** — a LEAF to the tip its remote serves for its `branch=`, an EDGE to the twin the SOURCE's tree records — while a path **with** a checkout is still rolled in that checkout, so the two keep agreeing. The fail-loud discipline is unchanged for everything the verb **cannot** advance: an unjudgeable path, a remote that does not serve the branch, a missing url, an unreadable source twin.

This change is the **consumer leg of that change in this repo**: the reference still taught the cost the product no longer has, in six sentences, in the places a reader actually reads them —

- the `charly task sync` row of the verb table;
- the bullet *"A pin wave needs the FULL set."*;
- the body of the bullet *"The pin is the INDEX entry; the checkout follows it."* (its TITLE survives — it is now exactly what the product does);
- the note *"`charly task sync`'s selection is also PARTIAL when the tree is not fully initialized"*;
- the seam paragraph, which said `bump` MATERIALISES each advance;
- the paragraph *"A fresh session worktree cannot run `sync` to a green exit, by design."*.

Each is replaced in the same cutover, and the wave's order is named where the guidance is read: **sync -> init -> verify**.

**What this change does not do.** It does not change the verb, the pin contract's states, the producer-first leg order, or the treatment of a `blocked-by` pin. It does not loosen what the file always said about failing loud: a path the verb **cannot** advance still fails the run, and a source with no checkout is still refused **by name**, with the command that materializes it. The umbrella's own three statements of the wave's order (`charly.yml`'s *"A WAVE NEEDS THE FULL SET"* comment, the README, and the umbrella's `AGENTS.md` Part II #3) are the umbrella's own leg, which follows this one; the umbrella's binary adopts the new verb in the `charly` leg, which also precedes it.
