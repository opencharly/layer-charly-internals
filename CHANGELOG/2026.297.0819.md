# 2026.297.0819 — docs(skills): state the pin-check verb's real read-set, not the edge alone (#146)

## Summary

The `git-workflow` skill's row for `charly task pin-check` described the verb as
asserting "the pin contract's cheap half — every `distro-*` gitlink equals charly's own
`box/*` gitlink" and called it "the cheap, commit-violable half of `verify`". **Both
claims are false as written**, and the false claim was not only stale prose: the
umbrella's commit gate took its change class from that same sentence, so a commit that
edited the manifest or the declared path set skipped the check that would have caught
it. The umbrella's half is fixed in opencharly/opencharly#661; this PR is the **corpus
half**, in the **authored** source of the sentence the umbrella copied.

**What the verb actually reads.** `charly task pin-check` composes `verb:git-submodules`
in `verify` mode, and that verb reads the **index's** gitlinks, the **manifest**
`charly.yml`'s `pins:` block and the **declared path set** `.gitmodules`; it asserts
the **EDGE** (every `pin_map` entry equals its twin in the `pinned_from` checkout) and
the **CHECKOUT AUDIT** (every declared path clean and at its recorded gitlink). So a
commit can violate it by moving a gitlink **or** by editing the manifest **or** by
editing the declared path set — a commit that moves NO gitlink can still violate it,
which is exactly the scoping the old row got wrong.

**What this changes.** Two rows in
`.agents/skills/git-workflow/references/umbrella-mechanics.md`:

| file | what it carries |
|---|---|
| `.agents/skills/git-workflow/references/umbrella-mechanics.md` | the `charly task pin-check` row, which now states the verb's real read-set and names the commit-carried inputs a commit can violate — and the **CONSISTENCY** row, which now names `charly task pin-check` as the same edge and checkout audit without the remote-branch audit, so "cheap" is replaced by the half it actually means |

Checkout **DRIFT** on its own — a checkout dirty or at another commit, caused by NO
commit — stays with `charly task verify`, and the row says so.

This is the **PRODUCER** leg of a four-repo cutover: `layer-charly-internals` (this
row) → `marketplace` (regenerate the corpus projection, which carries the same stale
row today and is generated, not hand-edited) → `docs` → the umbrella's
`layer-charly-internals` and `marketplace` gitlinks. Nothing in the umbrella is edited
to land this.

Closes #146.
