**What the guidance now says:**

- **ONE watcher per session; never stack `--auto-rearm` watchers.** The single-instance lock makes a re-arm take over a live peer, so extra arms are churn.
- **A 60-second poll FLOOR (`POLL_FLOOR=60`).** Every watcher defaults to 60s and REFUSES a sub-60s `--interval` at parse time (exit 5). `ALLOW_FAST_POLL=1` is the only escape hatch and is tests-only.
- **Prefer terminal-outcome events** (`merged,closed` + `stall`) over per-verdict/per-comment polling.
- **Budget the API explicitly**, with the measured rationale (below).
- The new **one-batched-GraphQL-poll** shape (calls-per-poll = 1 for the whole item list).
- A rate limit is a **HARD ABORT** (exit 7, `FATAL` naming the reset time), never a retry.

### The measured budget (pasted, reconcilable)

`gh_watch.sh`'s **`snapshot()`** on `origin/main` issues **6 REST calls per item per poll** — counted from the shipped source:

```console
$ sed -n '/^snapshot() {/,/^}/p' <orig>/gh_watch.sh | grep -c 'gh api\|watch_run_latest'
6
```

Deterministic two-round measurement (6 items, seed + exactly one poll; a sleep hook TERMs the watcher after the first sleep), call-counting `gh` wrapper:

```console
$ GHCOUNT_LOG=o.log ALLOW_FAST_POLL=1 <orig>/gh_watch.sh --events comment --interval 2 --timeout 20 <6 items>
$ wc -l < o.log
73
$ grep -c 'run list' o.log
12                       # 6 items x 2 rounds (seed + 1 poll)

$ GHCOUNT_LOG=n.log ALLOW_FAST_POLL=1 <new>/gh_watch.sh --events comment --interval 2 --timeout 20 <same 6 items>
$ wc -l < n.log
3                        # 2 api graphql (seed + poll) + 1 FREE api rate_limit
```

**The old 73 reconciles exactly with the 6-per-item rate:** `(73 − 1 free /rate_limit) ÷ (6 items × 2 rounds) = 6/item/poll`. Over 5 items that is 30 calls/poll — at `gh_watch.sh`'s own old **30s** default (2 polls/min) `6 × 5 × 2 = 3600/hr` (72% of the budget for ONE watcher), and at a then-reachable **20s** cadence `6 × 5 × 3 = 5400/hr` (**OVER budget**). The new billable constant is **1 GraphQL request per poll for N items** (new total = `polls + 1`, independent of N). Full evidence in the paired marketplace PR.
