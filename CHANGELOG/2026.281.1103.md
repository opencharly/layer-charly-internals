# 2026.281.1103 — docs(git-workflow): presence checks catch a missing fix, only absence checks catch a leftover one

## Summary

Adds the **fourth bullet** to the body-evidence rule set in the `git-workflow` skill's "BEFORE ANY UPDATE
PUSH" section — the **polarity** the other three were missing, from `retention`'s measurements tonight.

**The gap it closes:** every other bullet in the set — *assert every insertion*, *read the live body back
by named marker*, *name the head inside the fence*, *name the tree and the object* — is a **presence**
check. A body can satisfy all of them and still carry the sentence it was corrected to delete. Measured
twice in one evening: on `charly#843` the summary carried the correction while the **R1 bullet three
paragraphs later still asserted the retracted mechanism verbatim**, and on `plugin-clean#13` a *second*
`git log --oneline origin/main...HEAD` still printed the predecessor's commits under a "ran on this tree"
heading. Both bodies had been grepped for what was **added** and never for what was **removed**.

**The rule, as it now reads in the entity:**

> **Presence checks catch a MISSING fix; only an ABSENCE check catches a LEFTOVER one — after any
> correction, grep for the RETRACTED claim too.** So the pair is mandatory: grep that the replacement is
> present AND that the retracted string is gone (an empty result for the old text, pasted like any other
> check).

It sits **last** in the set, because it closes the set rather than extending it, and it is the cheapest of
the four: one grep, for the string you removed.
