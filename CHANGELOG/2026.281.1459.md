# 2026.281.1459 — docs(git-workflow): a claim is only as good as the object it names

## Summary

The eighth body-evidence bullet, beside the seven already merged (`#92`, `#93`, `#95`, `#96`, `#97`, `#98`):

> **A claim is only as good as the object it names - find what the words actually denote, then measure THAT.**

Three failures in one evening, one shape:

1. **A sweep searched a string that occurs nowhere.** The body searched `cloudimg-v<ver>` while the retired filename has no `v`, so its `total=0` was vacuous and would have let the real reference slip past.
2. **A measurement was presented as evidence for a different artefact.** `go list -m` reports the **build-list selection**; `go.work.sum` records **build hashes**. They are different objects, and the pasted first contradicted the diff it was meant to explain - the review caught it, twice.
3. **A step name denoted two commands.** A CI step NAMED `golangci-lint` failed, while the step runs **two** invocations under **two** environments (`charly/`, then each `tools/*` module with `GOWORK=off`). Naming the commands is what makes the failure addressable; **`the lint is red` was a claim about an object the step name does not denote.** *Its own RCA is tracked separately in `opencharly/charly#857` rather than resolved here - a re-run that comes back green is not an RCA, and stating that is the corollary this bullet now carries.*

**The cure is one sentence:** before explaining, proving or fixing, name the object - the string, the file, the command - and confirm the thing measured is the thing being talked about.
