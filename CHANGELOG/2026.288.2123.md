# 2026.288.2123 — docs(skill): the agents skill gains the lost-update rule - one writer, and a version guard on every write

## Summary

Adds the **lost-update rule** to the `agents` skill: *one writer per artefact, and a version guard on every read-modify-write.*

**Why here.** The section it lands in, `## Todo ledger & interruption safety`, owns the session's durable in-flight state and what survives an interruption — and it was missing the half that matters when **two sessions write the same artefact**. The authoritative-copy registry puts the agent/workflow primitives in `/charly-internals:agents`, so this is its home and not `git-workflow`'s, which documents only the downstream *symptom*.

**The rule, and why it is not a merge:** two sessions appending to the same ledger — or editing the same file — is a **lost update**. The second writer read a stale version, its write overwrites the first's, and **nothing reports an error**; the surviving artefact is one of the two, chosen by timing.

**The guard is the write's PRECONDITION**: read the artefact *with* its version, and refuse the write if the version moved — *a stale-version error IS this guard firing*, and the recovery is re-read, rebase the intended change onto the new content, retry. **Where no version is exposed, the durable substitute is a single writer**: one session owns the artefact and the rest hand work over through a coordination comment rather than writing it themselves.

**And the same defect one step earlier**, which is why it is one cutover and not two: *a status written from memory is a claim about the **wrong moment*** — the reader held a stale version and reported it as current. That is the mechanism that presents downstream as `a concurrent writer presents as a flaky test`.
