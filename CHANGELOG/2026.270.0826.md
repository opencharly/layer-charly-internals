# 2026.270.0826 — docs(internals): cross-session follow-up — commenter re-checks & reacts; PR owner acts on replies before the next push

## Summary

Extends the `git-workflow` cross-session coordination guidance (B2b) with the **follow-up
half** of the PR-comment channel, and tightens the pre-update-push invariant:

1. **The commenting session MUST follow up.** After posting a coordination comment on
   another session's PR, the blocked session re-checks that PR's thread for a reply at
   every natural step — before its own next push/commit, on resume, and at a BOUNDED
   cadence (a bounded poll, never a `sleep` loop — R4). When the owner answers, it reacts:
   proceed if unblocked, refine/answer if clarification is asked, or escalate to the
   operator if still blocked. A one-shot comment with no follow-up is the failure.
2. **The PR-owning session MUST read AND act on every comment/reply before its next push.**
   The pre-update-push read now requires ACTING on the thread: each comment (including a
   blocked session's reply) is answered in-thread or addressed in the pushed state.
   Pushing while an unanswered comment stands is a violation — the fresh `pr-validator`
   weighs the whole thread (comment intake).
3. The **"BEFORE ANY UPDATE PUSH" invariant** was updated to name the act-on-each-comment
   requirement alongside the read.
