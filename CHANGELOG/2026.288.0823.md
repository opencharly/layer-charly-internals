# 2026.288.0823 — docs(git-workflow,agents): a control that SKIPS is not a control; a queued check is delayed, not lost

## Summary

Two measured lessons from one night, named where the next session will load them. **Closes nothing** — no issue is claimed here; both are durable codifications of findings already landed elsewhere.

**1. `agents` — "A control that SKIPS is not a control."** Three occurrences of ONE defect, in one night, on three levels: a check that did not run — or ran against a narrower object than the claim — was read as a pass.

- a suite that proved the **FEATURE and not the CONTRACT** (a plugin's schema documented two edge shapes; the suite exercised one);
- a **live gate that drove only the already-guarded shape**, so the behaviour the change ADDED had no live execution at all and the gate still reached its PASS line;
- a control that **SKIPPED two of its five assertions** for want of uninitialized inputs, and printed `OK`.

The rule it yields: **read a control's OUTPUT, never its exit code or its headline.** A `SKIP`, an uninitialized input, an empty result set and a narrowed arm all render as green; count the assertions it claims, count the ones it ran, and make the two numbers agree.

**2. `umbrella-mechanics` — a queued required check is DELAYED, never lost, and cannot be re-run.** Placed beside the `task sync` base rule it belongs with.

- The validator needs the org's self-hosted `opencharly` runner label (four runners) while a repo's OWN CI runs on `ubuntu-latest`. **Two different fleets**, so a sibling job finishing in the *same second* says nothing about the validator's queue.
- Measured waits on that label: 47 s · 5 m 49 s · 11 m 57 s · 26 m 24 s · 1 h 1 m · **8 h 33 m** — and the run that waited 8 h 33 m **SUCCEEDED**. A multi-hour queue is the steady state under long-running org beds, **not a defect to file**.
- `gh pr checks` renders it `pending`, and `mergeStateStatus: BLOCKED` is then a statement about the QUEUE, not about the code.
- **A re-run is unavailable while it is queued:** GitHub counts a queued-only run as running, so `POST .../runs/<id>/rerun` answers `403 {"message":"This workflow is already running"}`. Wait it out — a run that produced no verdict is not a counting verdict.
